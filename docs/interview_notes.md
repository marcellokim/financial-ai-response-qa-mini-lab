# Interview Notes

## Positioning

This is a personal portfolio project for public-data-grounded AI response QA. The core value is not model building. The core value is evaluating response quality with traceable evidence, failure tags, and improvement insights.

## Allowed Claims

- Built a small QA lab using public finance data sources and public Q&A.
- Normalized public-source records into evaluation cases.
- Created public-source-derived response variants.
- Evaluated responses for accuracy, completeness, timing, safety, naturalness, and source traceability.
- Generated a Markdown report with failure tags and improvement insights.

## Forbidden Claims

- Evaluated a production banking AI.
- Used customer data or private conversations.
- Improved a real model.
- Built a financial recommendation service.
- Determined user eligibility for financial products.

## 30-Second Explanation

I built a personal QA lab that evaluates finance-related AI response candidates against public evidence. The workflow starts with public source records, normalizes them into test cases, evaluates response variants with a written rubric, and generates a report showing missing conditions, unsupported claims, timing gaps, unsafe wording, and source-traceability issues.
